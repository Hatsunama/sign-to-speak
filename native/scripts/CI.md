## Scope and use

Full Python host suites in the Android and Pocket component workflows provision only NumPy 2.3.2 into `$RUNNER_TEMP/sign-python-host-tests` before the suite. The Ubuntu 24.04 CPython 3.12 x64 wheel digest in `native/requirements-host-tests.txt` comes from the [official PyPI release JSON](https://pypi.org/pypi/numpy/2.3.2/json). The two-minute step requires a matching wheel hash, disables dependency resolution and the pip cache, and exports `PYTHONPATH` for subsequent steps. This is host-test preparation only; it does not install the reference audition stack or establish any model or asset license.

`.github/workflows/sign-android.yml` is a development-only workflow triggered manually or by a same-repository PR whose head branch is exactly `fix/android-native-foundation` or `codex/sign-to-speak-reply-app-20261121`. Fork PRs and other branches do not run the job. Candidate publication requires coordinating review; opening or updating an approved PR then triggers CI. It runs on the standard `ubuntu-24.04` hosted runner, one job bounded to 30 minutes, without persistent caches. Artifacts expire after three days. The source repository is public; logs and artifacts must contain only repository/build/test data, never user media or keys.

The checkout is the exact PR head SHA (not a synthetic merge commit), or the dispatch `GITHUB_SHA`, verified against `git rev-parse HEAD` and recorded alongside lockfile/wrapper hashes, run ID, runner image version, test reports and APK checksums. Do not describe a different or newer commit as tested. Every change needs a fresh run; rerunning an old workflow does not validate new code.

The Android, emulator-build and Roboflow tracker workflows use Rust 1.99.1 for the Android Pocket runtime. The shared builder installs that exact toolchain with the minimal profile when missing and uses it for target setup and all Cargo commands. Its per-ABI rustc and Cargo version report appears in the build log and the retained evidence for successful Pocket builds.

## Gates

1. Locked dependency install without lifecycle scripts; all Node host tests, TypeScript check, actual Java cancellation-class tests, and CI configuration/SDK-helper tests.
2. Preinstalled SDK36/build-tools36.0.0/CMake3.31.5, and exact NDK27.1.12297006. If missing, only that NDK may be installed, bounded to 180 seconds, using existing runner license records and standard input closed. There is no license-acceptance command or injected license hash. A new terms prompt, missing license, or download problem fails with an explicit blocker. Gradle automatic SDK downloading is disabled.
3. Preinstalled JDK21 is required by Robolectric4.16 for SDK36 (JDK17 remains sufficient for the standalone Java class check). Full `:app:testDebugUnitTest`, compiling production Kotlin and running Android-class tests with Robolectric's simulated framework. This is not an Android emulator, actual CameraX binding, or React Native bridge proof.
4. `:app:verifyDebugMergedPermissions` and `:app:verifyReleaseMergedPermissions`, checking the actual merged manifests, including transitive permissions. `--continue` lets both independent variant checks report even if the first fails. No release APK/AAB is built.
5. `:app:assembleDebug`, x86_64 only, with bundled JavaScript and an unsigned APK. Build success does not prove functional camera/UI behavior. Failed unit or manifest gates remain failures while other native evidence steps still run, provided host checks and SDK setup passed. APK upload requires overall success.

6. Opt-in `-PunsignedPhoneQa=true -PreactNativeArchitectures=arm64-v8a`: `:app:verifyUnsignedPhoneQaIsolation :app:verifyQaMergedPermissions :app:assembleQa`, followed by `scripts/ci-phone-qa-audit.sh` and the live-tracking, Pocket and Reply audits of that same final ARM64 QA APK. This produces an unsigned isolated test-only ARM64 APK, not a physical-device test. The separate [emulator build workflow](../../.github/workflows/sign-emulator-build.yml) produces/audits an unsigned x86_64 app/test pair without booting or installing.

No signing configuration is changed by the workflow. No AAB, release publishing, production keys or app-store action is included.

## Remaining emulator gate and signing precondition

An unsigned APK cannot be installed. Emulator instrumentation remains a required pending gate, not a skipped or simulated success. The isolated `.qa` app and `.qa.test` instrumentation pair already build unsigned. Before runtime work, obtain authorization for compatible app/test signing using the existing development key on C, approved signed-artifact transfer and a pinned emulator system image with already accepted terms. Keys stay on C: never generate, import, download or export a signing key in cloud CI. Use emulator-generated frames only; no personal camera feed, real phones, network user data or media artifacts.

## Pinned Robolectric native-runtime fallback

[Run 45042296191](https://github.com/Hatsunama/sign-to-speak/actions/runs/45042296191), attempts 1 and 2, completed the app compilation and other preceding work but failed before Robolectric executed because `repo.maven.apache.org` returned HTTP 429 for `org.robolectric:nativeruntime-dist-compat:1.0.18`. [Run 45048083679](https://github.com/Hatsunama/sign-to-speak/actions/runs/45048083679) then failed quickly when the fallback's distinct `repo1.maven.org` Central endpoint also returned HTTP 429. These runs provide no unit-suite, counterfactual or restored-candidate result.

The Android workflow now makes one bounded, no-retry curl attempt against the public Scandit Maven repository on Cloudsmith, a third-party mirror, before any Gradle or expensive Pocket build. Redirects are restricted to HTTPS. It accepts only the 159128857-byte `1.0.18` JAR whose SHA-256 is `a6c34d92c990754e5aee076032a36f8e38fcacb5eb878ebe0a324509f3864eef`, then places it with a minimal POM in a runner-temporary Maven repository. The digest is published in the Cloudsmith package listing and independently matches AOSP's `maven_install.json`; this matching metadata is checksum provenance, not a publisher signature or proof that the mirror is canonical. One generated Gradle init script grants that repository exclusive content only for `org.robolectric:nativeruntime-dist-compat` and configures the general Maven Central mirror described below. Size, digest, POM and init-script checks all fail closed before Gradle.

The exact Cloudsmith JAR URL returned HTTP 200 to a host-side HEAD check before this change. That observation does not prove a hosted runner's GET will succeed and does not attest to the bytes returned; only the workflow's exact length and SHA-256 checks admit the downloaded file. The workflow performs no HTTP retry, so an unavailable mirror, incomplete response or mismatched file fails the run. Its existing no-persistent-cache policy remains unchanged.

[Run 45050355401](https://github.com/Hatsunama/sign-to-speak/actions/runs/45050355401) checked exact head `f2f091c7ce2979b52998d73121b93a34971c9a16`. Its bounded Cloudsmith download returned the complete 159128857-byte JAR and passed the pinned SHA-256 check, but the first Gradle dry-run then failed during dependency resolution. Maven Central or the Gradle Plugin Portal returned HTTP 429 while resolving Kotlin stdlib 2.2.21, Kotlin Gradle plugin and BOM 2.1.20, and java-diff-utils 4.15. The run therefore supplies no Gradle task-graph, Android-unit, manifest, APK or phone-QA result.

The generated CI-only Gradle init script now places Google's hosted Maven Central mirror, `https://maven-central.storage-download.googleapis.com/maven2/`, before repositories declared later by settings and builds. `gradle.beforeSettings` covers plugin management for the main build and React Native included build; the same init script adds the mirror to every project's buildscript and dependency repositories. Every Gradle invocation in this workflow, including the first dry-run and the offline dependency report, receives the script. The exact locally staged Robolectric module remains an `exclusiveContent` repository with the same size and digest checks; this change neither relaxes that admission nor changes app dependencies. [Google Cloud documents this URL as its hosted Maven Central mirror and provides a Gradle configuration example](https://cloud.google.com/docs/buildpacks/java#google_cloud_hosted_maven_central_mirror); 2026 JetBrains support guidance also recommended the Google endpoint for new Maven Central HTTP 429 failures.

Before this change, host-side header-only requests returned HTTP 200 for the four missing POMs and the exact Robolectric JAR at the Google mirror. Those responses establish only endpoint presence at that time: they do not prove that a GitHub-hosted runner can complete GET requests, do not attest to returned bytes, and do not validate Gradle resolution. Only a fresh hosted workflow run can establish whether the mirror repairs this candidate; it still cannot establish emulator, physical-device, signing or release behavior.
