# Generation stop contract - November 19, 2026

The pinned Qwen model declares text EOS 248044, while its actual processor and our supervised assistant completions use turn EOS 248046. The default generation configuration therefore does not express the same boundary as the target loss. The first v4 evaluator rejected that valid default, and the first fit implementation could continue after the supervised turn. [Pinned model configuration](https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/config.json)

This was reproduced from the preserved same-model predictions and tests before repair. All 153 inspected saved generations ended with assistant EOS followed by token 198 and text EOS. Their decoded strings ended with a newline. For all 24 historical matched assessment rows, the pinned scorer reproduced the stored scores, and removing trailing newlines left every exact/CER value unchanged. The historical base/A/B 0/8 findings remain preserved. This diagnostic does not rerun or requalify those models.

The current shared input/completion helper resolves the attested tokenizer EOS first and distinct valid model special stop tokens afterward. Fit and evaluation explicitly pass `[248046, 248044]` for this model. They record the effective stop IDs and reject returned tokens after either boundary. They do not silently truncate a broken generation result. Generation remains greedy, capped at 32 new tokens, with prefix-only inputs; teacher forcing retains its original masked targets and assistant EOS. [Completion contract](fsboard_task_inputs.py) - [Fit](fsboard_task_fit.py) - [Evaluation](fsboard_task_evaluate.py)

This necessarily changes research generation behavior at the assistant boundary. It changes no production app appearance or behavior. Existing metric functions and historical result files are unchanged. The frozen six-clip fit policy is now v2, before any v4 fit model has run. Original v1 policy/source archives remain private and in Git history. [Current fit policy](FSBOARD_V4_FIT_SMOKE_PROTOCOL.json)

The corrected input gate's encoder function is unchanged from the running CPU admission/processor source. Its additional EOS helper does not alter frames, tokenization, labels or the existing eight-field processor attestation. The next GPU source package binds the new consumer code independently and must verify actual generation at checkpoint zero. Passing mock tests is insufficient proof of CUDA generation, gradients or fit.

Carry this stop policy into future merged/quantized model exports and native generation. Verify the exact tokenizer metadata, first end-of-turn stop, token cap and cancellation in the exported model/runtime, then in the final APK on both available phones. A model config, conversion, installation or previous APK run cannot establish that behavior for a new artifact. No v4 model or release is qualified here.
