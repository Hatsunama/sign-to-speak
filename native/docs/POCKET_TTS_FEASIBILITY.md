# Pocket TTS feasibility for local English speech

Checked 2026-10-25. **Phase 1 decision: admit a bounded conversion experiment, not a production speech model.** Kyutai's October 2026 small English models offer a plausible permissively distributable text-to-PCM path without eSpeak or OpenRAIL-M. The existing community LiteRT Android implementation is useful source, but its published graphs, hard-coded tensor shapes and Pixel measurements apply to the older roughly 100M-parameter English model. No small-model LiteRT conversion, APK, speech quality, phone performance or peak PSS was verified here. No weights or graphs were downloaded; no build or device was run.

## Android and text contract

Kyutai's small configurations specify a 4,000-piece **SentencePiece text tokenizer**, not a phonemizer or eSpeak data path. They specify 24 kHz mono audio and 12.5 latent frames per second. The [LiteRT Kotlin tokenizer](https://github.com/geneing/PocketTTS-LiteRT/blob/be0e64ca82c00e255ac6dd04e440e13a64bdc532/pockettts-core/src/main/kotlin/dev/pockettts/SpTokenizer.kt) ports SentencePiece unigram tokenization without JNI and its README reports parity on 613 strings **for the old tokenizer**. Regenerate its TSV from the selected small model's pinned `tokenizer.model`; compare exact token IDs with Kyutai's reference for punctuation, names, numbers, abbreviations, unseen words and Unicode. The three small configs explicitly map en/em dashes to commas and curly apostrophes to ASCII; preserve the reviewed text in the UI and test the spoken effect of those replacements. No claim of reliable pronunciation follows from absence of GPL components. Use the existing protected app-owned PCM/AudioTrack path, chunk/cancel ownership and review-before-speak policy.

The community [converter](https://github.com/geneing/PocketTTS-LiteRT/blob/be0e64ca82c00e255ac6dd04e440e13a64bdc532/scripts/build_pockettts.py) currently calls `TTSModel.load_model()` with the default old model and hard-codes 1024-wide, six-layer, 16-head flow LM tensors and a 32-dimensional latent. The [18M config](https://github.com/kyutai-labs/pocket-tts/blob/a922b912dfa366975294afb568d815b305acde5d/pocket_tts/config/english_18m_2026-10.yaml) instead has eight 512-wide layers, eight heads and a 64-dimensional latent; 7M and 2M change dimensions and attention further. Voice KV-cache shapes, embedding lookup, flow head, codec decoder, fused graph I/O, constants in `PocketTts.kt`, Kotlin buffer allocation and token table must all be generated from the selected config and parity-tested. The 2M decoder also changes layer count. A filename replacement or direct load of the published graphs cannot work.

The port uses `com.google.ai.edge.litert:litert:2.2.0` and Android `CompiledModel`; [the README](https://github.com/geneing/PocketTTS-LiteRT/blob/be0e64ca82c00e255ac6dd04e440e13a64bdc532/README.md) reports about 1.0× real-time on a Pixel 8a for its **old full-size model**, with decoder transformer placed on CPU after audible GPU degradation. Its newer Pixel 10 CPU/NPU/GPU results are likewise for that model and hardware. The README says its old six-voice fp16 package is about 225 MB and graph loading costs seconds and about 150 MB native memory. Its architecture sends a large packed KV cache through accelerator buffers; smaller parameter count alone does not establish lower peak PSS or a 1.5-second first-audio result. Treat all such figures as third-party measurements, never as this app's phone evidence. The converter's documented stack requires Linux/WSL2 or macOS because its conversion wheel is unavailable on Windows; do not launch that workload on the low-RAM host by default.

## Bounded next implementation and gate

1. On a suitable separate conversion host, pin the exact official source commit, ungated HF revision, **all selected LFS SHA-256 values**, converter commit and dependency lock. Generate one `english_18m_2026-10`/Alba graph-and-assets set, with an automated reference-vs-LiteRT parity check for token IDs, latent steps, termination and decoded 24 kHz PCM. Include conversion changes and CC BY indication-of-changes in the notice manifest. Generate only the graphs the runtime loads, not unused alternates or other voices.
2. Adapt only the needed MIT Kotlin core into the app's existing native speech boundary. File contract: local verified model/voice/tokenizer assets under a versioned root; no hosted call or runtime downloader; input reviewed Unicode text plus cancellation generation; output bounded 24 kHz mono PCM chunks to the existing AudioTrack owner; stale synthesis never becomes audible. Define corrupt/missing-model failure, background/Stop disposal and model-hash rejection before UI integration. Check the LiteRT AAR, its transitive dependencies, native ABIs, manifest and 16 KiB page alignment on the eventual exact APK. Preserve the current no-INTERNET policy.
3. Run a fixed listening/pronunciation set and the actual native phone probe on both free target phones. Record cold load, first audio, real-time factor, peak PSS, 100 start/stop cycles, cancellation, thermal behavior, model bytes on disk and APK delta. Compare 7M only if 18M's quality/latency/size tradeoff warrants it; do not choose 2M from parameter count alone. Owner acceptance of the selected voice remains the Phase 2 gate.

**Decision boundary:** CC BY 4.0 model and Alba attribution plus MIT notices can be prepared as ordinary release obligations; an owner license preference is not needed to start this narrow experiment. The remaining admission blockers are a reproducible small-model conversion, exact file rights/notice inventory, measured speech quality and successful execution within this product's Android privacy, latency and memory gates. Pocket TTS does not resolve continuous ASL translation or reply ASR feasibility.
