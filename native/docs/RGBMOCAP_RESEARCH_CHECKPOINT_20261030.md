## Important incompatibilities

- The inspected inference stages explicitly require CUDA: [worker.py:323–334](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/mocap/worker.py#L323-L334). This is a Windows/PyTorch recorded-video animation system, not an evidenced Android tracker.
- HandFlow runs 16-frame windows with overlap and estimates missing motion. Its output is `(frames, 2, 15, 3, 3)` finger rotations, not MediaPipe's 21 hand landmarks: [handflow_engine.py:143–163](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/mocap/handflow_engine.py#L143-L163). No direct mapping into the current 543-point classifier or proposed 208-feature translator is proven.
- Detection validity is saved with predictions, but partial missing intervals still become finger rotations in the merged body output; only an entirely unobserved side receives the default pose ([handflow.py:78–116](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/mocap/handflow.py#L78-L116)). This is acceptable to assess as animation completion, but using unflagged estimates as signing observations risks plausible incorrect meaning. This is an ASL adaptation risk, not proof that the original animation app is defective.
- Hand contact correction pins low-motion palms to anchors ([hand_lock.py:28–60](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/mocap/hand_lock.py#L28-L60)). Do not use support/contact correction to alter recognition input; meaningful holds, contacts and small movements must survive.
- The working video is resampled to 30 fps ([video.py:146–161](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/mocap/video.py#L146-L161)). Our evaluation must retain actual decoded timestamps and identify repeated/dropped frames rather than assuming a requested cadence was observed.
- Original wrapper code is MIT, explicitly excluding third-party models/derived code ([LICENSE](https://github.com/toyxyz/toyxyz_RGBMocap/blob/892193b113881d3f1d9fc18aa2d0bde9537b983d/LICENSE)). HandFlow/HaMeR source grants do not settle every weight/body-model term. GVHMR's inspected license restricts commercial use; FlowHMR's source is Apache 2.0 with separately licensed supporting assets. No model or third-party source was copied into Sign to Speak.

## Recommended next implementation boundary

Keep the current renderer/React Native UI and rear/front preview behavior. Build native Kotlin processing behind the existing camera lease:

`CameraX + recorded-video frame source → timestamp/rotation/crop transform → selected-signer Holistic observations → explicit hand/face/pose validity → bounded temporal history → separately admitted recognition adapter → reviewed text/status`

Raw camera images and landmarks stay native and volatile. React Native receives the existing bounded status/text events. Stop, Back, backgrounding, lens changes and tracker errors invalidate the relevant epoch and release owned resources.

MediaPipe Holistic already has pose-guided hand/face regions and dedicated hand tracking; inspect the pinned graph before adding a second detector. Begin with the existing source-built offline SDK and pinned model that executed in QA; admitting it into production requires the same actual-APK dependency/notice/no-network checks. Do not reintroduce published telemetry dependencies by copying `latest.release` sample configuration.

Tracking engineering can be evaluated independently of the unresolved sentence-model contract. It must not guess the recognition adapter. First acceptance should cover orientation/mirroring, two-hand crossings, hands near face/body, occlusion/reacquisition, actual timestamps, bounded buffers, old-callback rejection and lifecycle cleanup using licensed annotated videos. Compare visible-hand coverage, handedness swaps, keypoint error, temporal delay/jitter and dropped frames. Smooth appearance alone is insufficient; existing four-clip top-1 matches are not a tracking/ASL quality benchmark.

Remaining research: verify the exact pinned Holistic graph's internal ROI behavior and API ownership contract; choose measurable tracking thresholds on licensed reference video; then implement and test the native frame path before any optional second-stage hand refinement. No performance or accuracy gain is claimed from source inspection alone.
